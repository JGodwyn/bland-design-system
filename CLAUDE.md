# Bland Design System

Bland is Godwin's personal design system: a Figma UI kit reused across client projects, being turned into code with a token pipeline and (later) a docs site. Figma is finished; this repo is the code side.

- Light and dark themes. A per-project brand color: a project overrides the 13 `--brand-*` steps (and the 13 `--neutral-*`, tinted toward its brand or pure gray) at `:root` and everything follows (`docs/brand.md`). Up to three extra project colors (charts, illustrations, its own UI) get 13 steps and light/dark roles each; Bland's components never use them.
- Inter for text, Geist Mono for code (a project sets its own through `--font-body`, `--font-heading` and `--font-code` in its `brand.css`), Phosphor icons, 100% corner smoothing on every rounded corner.
- One-person system (Godwin plus Claude). Keep process light: no review flow, no client-facing docs yet.

## Hard rule

**No hardcoded values in component code.** Every color, size, space, radius, stroke, shadow and type value is a `var(--…)` token. If no token fits, stop and ask; do not invent a value or a token.

### Export rules

Implemented in `scripts/build-tokens.ts`; CSS naming and the sync steps are in `docs/tokens.md`.

- Output is CSS custom properties (`--space-md`, `--surface-100`, …). Dark mode redefines the Theme variables only. No Tailwind theme.
- In components, use the composites: `font: var(--type-body-md)`, `box-shadow: var(--elevation-neutral-mid)`.
- Resolve alias chains to final values. Theme tokens alias primitives in both modes.
- Component tokens alias primitives directly, never another component's tokens (so they can diverge). Sole exception: `Badge/*` aliases `Indicator/*` on purpose.
- Alpha primitives are stored as `{color: alias, opacity: N}`. Resolve to the source color at that opacity.
- **Do not export `Fade/*-clear`** (Figma-only drawing aids).
- Export every variable's description alongside its value.
- Elevation: 15 styles `Elevation/{neutral,brand,danger,success,warning}/{near,mid,far}`, each an ambient + key layer. Geometry from `Effects`, color from `Shadow/{family}-{ambient,key}`. In code each is **one `box-shadow` variable** whose color switches in dark mode.
- Text styles: Display, Heading, Title, Body (incl. `-bold`, `-underline`), `Code/*` in Geist Mono. Each is a `font` shorthand (`--type-body-md`) plus `--type-body-md-line-height` and `--type-body-md-letter-spacing`; set the letter spacing beside the `font`. The family is a role token: `var(--font-body)` in Body, `var(--font-heading)` in Display, Heading and Title (it is `var(--font-body)` until a project sets it), `var(--font-code)` in `Code/*` (Godwin 2026-10-30: named by role so any font fits, Title counts as a heading). These three family tokens are the only font tokens (Godwin 2026-10-29, reversing the earlier no-`--font-*` rule, so a project can swap its fonts in `brand.css`; `docs/brand.md`, "Fonts"). Still no `--font-size-*`, `--font-weight-*`, `--line-height-*` or `--letter-spacing-*` tokens. Components keep using the `--type-*` composites. `weight/semibold` (Inter "Semi Bold") and `weight/mono-semibold` (Geist "SemiBold") are both real: the families spell the style differently.
- Naming: size steps follow value order (`xs` < `sm` < `md` < `lg`). Variant values lowercase; property names capitalized.

## Decisions code must follow

- **Dark mode switch (Godwin 2026-10-27): both.** `data-theme="light|dark"` on any element wins (nested sections work); without it `prefers-color-scheme` decides. This is how `tokens.css` is generated; a project's theme toggle sets `data-theme` on `<html>`.
- **Dark mode:** Neutral mirrors (0↔950, 50↔900, …); color tints (50–300) become deep tones; color solids (400+) move two steps lighter. `surface-sunken` / `surface-raised` / `surface-raised-hover` don't mirror (a gray page with white cards stays darker than its cards in dark; Godwin 2026-11-02, `INTERFACE.md`). Parts that are white in light use `surface-raised`; fields and small fills inside controls use `surface-field` (see-through, so they read on any surface; Godwin 2026-11-02; Brand950 at 6% in light and Brand50 at 6% in dark since 2026-11-23, so fields carry the brand's hue, `INTERFACE.md`); any other area that should sit one step apart from whatever it is on (a panel in a panel, a table stripe) uses `surface-alpha` / `-alpha-hover`, same values, kept separate (Godwin 2026-11-20). Toggle knob is white in both modes. Danger primary Badge/Indicator label stays white in dark (3.7:1, deliberate). Success primary Badge/Indicator label stays white in light (4.47:1, deliberate, decided 2026-10-18).
- **Focus:** `:focus-visible` only, never a state or prop. 2px ring (`stroke-lg`) in `Border/border-focused`, offset 2px. Figma's `👀 Focused` boolean is dropped in code.
- **States:** rest, hover, pressed (where relevant), disabled. Selected and checked are their own props.
- **Slots:** Figma `🧩` slots map to `children` or named slot props.
- **Prop names:** strip Figma prefixes (`👀` boolean, `✏️` text, `🌟` instance swap, `🧩` slot).
- **Corner smoothing:** components set `--bland-radius` to the Figma radius and add `.bland-smooth`, which draws twice that radius with `corner-shape: superellipse(2)` (Figma's 100% smoothing spreads the curve over 2× the radius; tuned 2026-10-18). Safari/Firefox fall back to plain rounding at the Figma radius; that is accepted.
- **Icons (decided 2026-10-17):** Bland ships no icon pack. Every icon prop takes any SVG as a React node; Bland sizes it from `icon/*` (12, 16, 20, 24) and colors it through `currentColor` from the matching `Icon/*` token. Stroked icons (the Figma set, Lucide) get `stroke-md` (1.5) at every size; filled packs (Phosphor React, any weight) keep their own weight. The design source is the Phosphor-based Figma Icons page; the few icons Bland needs internally (spinner, caret, close, check) are exported from it into `src/icons/` as components need them. Details in `docs/components.md`.
- **Overflow:** every overflowing scroll area shows **both** a scrollbar (thumb `Scrollbar/thumb`, width `scrollbar/width`) and an edge fade. **The scrollbar shows only while the area scrolls** (Godwin 2026-10-22): it appears on scroll, stays while held or under the pointer, and fades out over `duration/md` once scrolling has stopped for `duration/scrollbar-hide-delay` (1000); the fade is always there. The fade is a real `mask-image: linear-gradient(...)` on the scroll container, transparent only on edges with hidden content, length `fade/md` (32) by default or `fade/sm` (16), updated on scroll; a focused item scrolls clear of it. (Figma's surface-colored overlay is only a workaround.) In code every fade uses the shared `.bland-scroll-fade` class; don't write another mask. Scrolling in Figma today: Menu, Calendar month/year, Sidebar, Code snippet, Text Area. Table, Modal body and chat list follow the same rule if they scroll in code. **Exceptions, fade alone with no scrollbar:** tab rows (Section, Pill, File tab) scroll sideways (Godwin 2026-10-19; a vertical wheel scrolls them sideways), and the Sidebar's list (Godwin 2026-10-20).
- **Disabled:** disabled states use the disabled color tokens (`Button/*-disabled`, `Toggle/*-disabled`, `Control/checked-disabled`). No opacity, and no opacity token; the lint rejects `opacity` on disabled selectors.
- **Page grid** (Godwin 2026-10-28): optional `.bland-grid` in `base.css`. Column width and gutter set the design, margins are what is left: 4 / 6 / 8 columns (mobile, `md`, `xl`) whose width is the widest multiple of 8 inside a minimum margin (space-lg, space-2xl, space-6xl), gutters space-sm then space-lg, desktop columns at most 128, 144 from `2xl`, 160 from `3xl` (`Layout/max-width-sm/md/lg`), centred; `--bland-grid-margin` raises or lowers the minimum (landing page, dashboard); children span `--span` / `--span-md` / `--span-xl`; `data-inset` for nested grids. Figma has nine matching grid styles (Mobile, Tablet and Desktop sm/md/lg) on every Screen templates variant; the Dashboard styles were removed (`docs/grid.md`).
- **Layout:** mobile-first. Base styles are mobile, `breakpoint/md` (768) is the tablet layout, `breakpoint/xl` (1280) the desktop layout; `sm`, `lg`, `2xl` and `3xl` are for component-level tweaks (the page grid also widens at `2xl` and `3xl`). Media queries use `min-width` on a breakpoint value only (`var()` does not work there; the lint holds the list). `--breakpoint-*` exist for JS (`matchMedia`, Floating UI).
- **Motion:** details and reasons in `docs/motion.md`.
  - Durations and easings are Motion tokens only. Never `ease-in` on UI; entering and exiting use `easing/out`.
  - UI motion stays at or under `duration/lg` (250). Only Toast (`xl`) and Sidebar/sheets (`2xl`, with `easing/drawer`) go above. Loading spinners rotate continuously at `duration/spin` with `easing/linear`; typing dots wave continuously at `duration/typing` with `easing/in-out`.
  - Don't animate keyboard-initiated actions or anything used hundreds of times a day.
  - Never scale from 0: start at 0.95 to 0.97 with opacity 0. Popovers, dropdowns and tooltips scale from their trigger; modals stay centered.
  - Press feedback: `scale(0.97)` on `:active`, `duration/sm`, `easing/out`.
  - Exit along the same path as the entrance, quicker: popovers close in `duration/xs`, open in `duration/md` (Godwin 2026-10-27).
  - Every animation has a `prefers-reduced-motion` fallback: keep opacity and color, drop transform motion.
  - Gate hover motion behind `@media (hover: hover) and (pointer: fine)`.
  - Name exact properties, never `transition: all`.
  - Stagger lists 30 to 80ms per item. No stagger token until a component needs one.
- **First-line alignment** (Godwin 2026-10-27): text in a row with an icon, buttons or other items is centred with them while it is one line, and everything stays at the top (lined up with the first line) once it wraps. `align-items: flex-start` plus a half-the-difference offset on the shorter items, never `align-items: center` on a row whose text can wrap. Recipe in `docs/components.md` (CSS).
- **Truncation is not overflow:** truncated text always ends in an ellipsis, never a fade.
- **Tooltip placement:** Floating UI names (`top-start` … `right-end`).
- **Writing:** descriptions and docs never use em dashes.

## Code stack

Raw build: plain CSS on token variables (decided 2026-10-17: plain classes, not CSS Modules). Classes are `bland-<component>`, variants are data attributes (`data-size`, `data-type`), parts are `bland-<component>__<part>`. **No Tailwind, no shadcn.**

- **Raw HTML components:** Button, Badge, Indicator, Chip, Avatar, Alert, Banner, Toast, Progress, Breadcrumb, Table, Empty State, Accordion (`<details>`), Toggle, Checkbox, Radio (native inputs).
- **React Aria for behaviour only** (keyboard, focus, screen reader); all styling is Bland CSS: Dropdown/Menu, Modal, Tooltip, Tabs, Slider, Date and Time pickers, Pagination input. Chosen over Radix and Base UI for focus handling and date components.
- **Positioning:** Floating UI for Tooltip and Dropdown. Native `<dialog>` and `popover` are fine where they fit; don't rely on CSS anchor positioning yet.
- **Framework:** React (confirmed 2026-10-16). It's the standard for design systems and React Aria requires it. Tokens stay plain CSS, so non-React client projects can still use them.
- **Lint:** Stylelint with a strict-value rule rejects any color, size, space, radius, stroke, shadow or font value that is not `var(--…)`. Each error names the token to use and why, so an agent can fix it in one pass. Set this up before building components.

## Workflow

1. Godwin changes a token, style or component in Figma.
2. Token sync: read variables through the Figma MCP, write token JSON into the repo, regenerate CSS, as one commit/PR whose diff shows exactly what changed.
3. Components pick it up because they only read tokens.
4. A decision made while coding goes into `docs/` or this file **in the same commit**, and the matching Figma description gets a one-line pointer.
5. Changing a component means updating its row in the component map in the same commit.
6. Renaming or removing a published token, prop or component follows the deprecation policy (`docs/release.md`, "Deprecation"): the old name keeps working, with a warning, for one minor version. A token sync that drops or renames a variable stops and asks first.

A drift-check script compares Figma variables with repo tokens and reports differences (optionally as a weekly scheduled task).
