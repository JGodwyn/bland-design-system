Read this first in any new chat about Bland. It holds the state of the work, the IDs needed to continue, and how Godwin wants the work done. Keep it current: update the "Status" and "Key IDs" sections whenever something changes.

## How Godwin wants the work done

- Flag strategic and scope implications before executing; propose, then build once agreed.
- **Always leave the page arranged when a component is done** (Godwin, 2026-10-15: he had to fix the tab pages by hand after the grids were reflowed). Inside each component set: Size in columns (sm, md, lg), every other property combination in rows (Selected false then true, State rest/hover/disabled, counts like Tabs from high to low), 24px padding and 24px gaps, variant layer order matching the visual order. If Size columns would make the set wider than about 1,400px, use a single column ordered by Size first. A set with one property and two or three values sits in one row. Then restack the set's page frame (the `layoutMode: NONE` frame holding the sets and the Notes instance): children top to bottom in their existing order, left-aligned, gap 72, frame padding 80/160 (80 top and bottom, 160 left and right; the Tab bar page frame is 160 + 432 + 160 = 752), frame resized to contain them, so nothing overlaps or spills out. If the frame is FILL inside its page wrapper, set it to FIXED before resizing. Finish with a screenshot of the whole page frame. (Structure, checked on Lists 2026-10-15: each page has an outer VERTICAL frame holding a `Header` instance, the NONE frame, and a `Footer` instance; Header and Footer are fixed width, so resize them to the NONE frame's width after restacking. Padding 80/160 was applied as 80 top/bottom, 160 left/right. Other pages measured differently, e.g. Empty State's inner frame has 104/148, so check with Godwin if he wants one value everywhere. The Pagination outer frame is auto layout and resized itself. When the outer frame grows, shift the page's Stickersheet and How to use frames right by the same amount so they do not overlap, as done on Modals.) **Resize the NONE frame first, then place its children** (Date & Time, 2026-10-15): resizing moves children by their constraints (the picker sets jumped up behind the Header); set each child's constraints to MIN/MIN and position after the resize. Variants with an absolute child that hangs below them (the open Dropdown menu) need the row height taken from the child's bottom edge, or the next row overlaps.
- Be careful with Figma credits: batch work into as few `use_figma` calls as possible; credits should mostly go to building components to spec. Do small manual-type tasks only if asked. Godwin does not care about the Landing page (2026-10-15): don't spend calls fixing or restoring it.
- No hardcoded values in components: every color, spacing, radius, size, stroke, effect and type value is bound to a variable. (Slider 2026-10-15: the value is not a width at all. The track is a one-row grid whose bar columns are FLEX (fr) tracks, so the value is the fr ratio, e.g. 70fr / 30fr; designers change it per instance in the grid column settings.)
- Use auto layout wherever possible (Godwin, 2026-10-15, on Slider): build tracks, rows and stacks as auto layout frames rather than absolutely placed layers with constraints.
- Proportional layouts: when parts must keep a ratio as their container resizes (slider value, split panes), use a GRID auto layout with FLEX (fr) columns and HUG columns for fixed pieces. Set `layoutMode = 'GRID'`, `gridRowCount`, `gridColumnCount`, `gridColumnSizes = [{type:'FLEX',value:70},{type:'HUG'},...]`, place children with `setGridChildPosition(row, col)`, `gridChildVerticalAlign = 'CENTER'`, FILL on the flexible children. `gridColumnGap` binds to a Spacing variable. `gridColumnSizes` can be overridden on a nested frame inside an instance (tested 2026-10-15). A FLEX track is invalid when the grid container hugs, so the grid needs a fixed or FILL width. (Calendar 2026-10-15: the day grid is 7 HUG columns of fixed cells; the month and year grids are 3 FLEX columns in a grid whose width is bound to `calendar/width-*`. Converting a wrap row to GRID: set `layoutWrap = 'NO_WRAP'`, then `layoutMode = 'GRID'`, then place every child.)
- Units rule: `_Units` holds the dimension primitives, named by value: `unit/0`, `unit/0-5`, `unit/1`, `unit/1-5`, `unit/2`, `unit/4`, `unit/8`, `unit/12`, `unit/16`, `unit/20`, `unit/24`, `unit/32`, `unit/40`, `unit/48`, `unit/56`, `unit/64`, `unit/72`, `unit/80`, `unit/128`, `unit/152`, `unit/168`, `unit/224`, `unit/256`, `unit/280` (the three added 2026-10-15 for `calendar/width-*`: seven 24/32/40 cells), `unit/384`, `unit/512` (added 2026-10-15 for `modal/width-md`), `unit/640` (added 2026-10-15 for `pagination/width`), `unit/full` (100000, pill radius). Figma variable names cannot contain dots, so halves use a dash. Every Sizing, Stroke, Spacing and Corner Radius token must alias a unit; never set a raw number. If a needed value is missing, prefer snapping to an existing unit (Godwin chose 4 over adding a 6 for the Radio dot, and 32 over adding a 28 for the Badge xl height); add `unit/<value>` (scopes empty) only when snapping would hurt, and say which in the proposal. Typography and Effects stay self-contained scales with raw values by decision (type sizes and shadow geometry should not move when the spacing scale changes; Effects also has negative spreads).
- Component color tokens point at primitives, not at another component's tokens (Godwin, 2026-10-15, on File Upload: "do it the same way list's own is", because he may want them to differ later). When a new component should look like an existing one, copy the primitive values into its own tokens instead of aliasing the other component's tokens. (The `Badge/*` to `Indicator/*` aliases are an older exception he chose.)
- Native slots: Godwin wants every manual slot (a `Square - Slots` instance behind a `🌟 Slot` instance swap, often paired with a `👀 Slot` boolean) replaced with Figma's native slot (`SLOT` property). Avatar, Chip, Empty State, File tab, List, Accordion, Modal body, Table cell/header, Sidebar, Calendar, Menu item, Dropdown trigger and `_trailing-input` are done; Tooltip and `_leading-input` still need it; queued pages convert during their own pass. See the native slot technique below. Icon swaps (`🌟 Icon` with a Phosphor default, as on Pills, Breadcrumb, Icon Button) are not manual slots and stay. Godwin also prefers a native slot over an instance swap for open-ended content such as illustrations (Empty State, 2026-10-15); ask when unsure. Native slot properties are named with the `🧩` prefix (`🧩 Slot`); some pages already had a native SLOT under the old `🌟 Slot` name (Accordion did): rename it. When a component has two slots, Godwin names them `🧩 Top slot` / `🧩 Bottom slot` with matching `👀 Top slot` / `👀 Bottom slot` booleans (Avatar, Modal body, Sidebar); side-by-side slots are `🧩 Leading` / `🧩 Trailing` with `👀 Leading` / `👀 Trailing` (List, Table, Menu item).
- Descriptions (components and tokens) are written without em dashes.
- Content color tokens: a component token that colors the text and icons sitting on a fill ends in `-content`, not `-label` (Godwin, 2026-10-15), e.g. `Badge/danger-primary-content`, `Button/danger-content`. Use this suffix for new components too.
- Color scales are generated in OKLCH.
- 100% corner smoothing on every rounded layer (cannot be a variable; set per layer).
- Optical alignment of leading icons: a 20px (`icon/md`) icon next to 24px-line-height text sits in an `icon-wrap` auto-layout frame (HUG, no fill) with top padding `space-2xs` (2), so it centers on the first text line and stays there when text wraps. The wrapper carries the icon's visibility property. Godwin set this pattern on Notification (2026-10-15); Alert, Banner, Toast, the Modal title, the Accordion chevron (trailing) and the File Upload row icons use it too; reuse it for similar components. (If Notification no longer shows `icon-wrap`, check with Godwin before re-adding it.) Single-line items (tabs, table cells, sidebar items) center the icon with items-center instead; no `icon-wrap` needed.
- Icon size in controls (Godwin, 2026-10-15, on Table): a 12px icon inside an xs Icon Button reads too small in a table cell. Use the sm Icon Button (32, 20px icon) or larger, and centre icon-only controls in their cell like checkboxes and radios.
- Reuse before inventing: new components should reuse finished pieces (Button, Icon Button, Checkbox, Indicator, Avatar, Tooltip, Tooltip pointer, Notification status model, Pills, Progress-bar, Text Input, Pagination item) as instances, and reuse existing token groups (Badge, Table, Menu, List, Date/Calendar-item theme tokens already exist). Pill tab is built from Pills instances (Godwin, 2026-10-15); the uploading File Upload row nests a Progress-bar; Table cells nest Checkbox, Radio Button and ghost Icon Buttons; the Calendar title bar arrows are exposed `_pagination-item` instances; the date and time pickers are thin wrappers around an exposed Text Input (and an exposed Calendar when Open). But a nested piece must match its host's shape: Godwin rejected the fully rounded Indicator as Chip's count because the chip's corners are not fully rounded, so Chip has its own square count box matching its close box (Section tab and the Sidebar item follow the same rule). Pills (fully rounded) keeps a nested Indicator. A nested Indicator needs `isExposedInstance = true` so its number is edited on the nested instance, since a parent TEXT property cannot drive a nested instance's text. Exposure chains work too: Slider exposes its `_knob` thumbs and each knob exposes its Tooltip, so designers set a thumb's State, `👀 Focused`, `👀 Tooltip` and the tooltip text per thumb (2026-10-15). Per-thumb or per-item state on an exposed instance avoids multiplying the parent's variants. Modal exposes its title, body and action bar the same way, File-upload exposes its uploader, and Dropdown exposes its trigger and menu.
- After any "MCP server connection lost" error, run a read-only check before retrying; so far every interrupted call had fully committed.
- `use_figma` returns are capped at about 20 KB: inspect with compact, deduplicated output (group layers by path, list distinct descriptions per path). A failed call commits nothing, so an unknown API can be tested in a dry run that ends with `throw new Error('DRYRUN ' + log)`.
- Finding layers by `componentPropertyReferences` can miss: one Banner variant's icon badge did not carry the `👀 Icon` reference its siblings had (and a minimized File tab variant's close box had none). Find layers by structure (for example "frame holding an `li:*` instance") and throw a clear error if any variant misses one.
- Destructive writes (deleting variants, layers or properties, remapping instances) need an explicit approval that names the specific changes. List the deletions and remaps in the proposal (lettered A, B, with ids) and ask for approval of that list. Godwin may ask why before approving; answer, then a reply like "go on with your suggestions" or "go on with all" after that exchange has been enough "do what you recommend" approved the Lists list and the Pagination list (2026-10-15). On Slider, "i approve A to E ... go on" was taken as also accepting the recommended options for the open choices. On Modals, "go on with all" approved the A to D list and the recommended options (sm/md/lg with `unit/512`, `Modal/surface`, trailing primary); Godwin later had the lg size removed. On File Upload, "go on with your suggestions" approved the list and the recommended options (nested Progress-bar, hover and drag-over states). On Table, "go on with all" approved A to F and the recommended options. On Sidebar, "yeah, go on" approved A to E and the recommended options. On Date & Time, "do everything you suggest" approved A to F and the three recommended choices. On Dropdown, "approved. go on" approved A to F and the recommended options (trailing Check for single select, `menu/width` 256). On Messaging, "go with your suggestions" approved A to F and the four recommended choices (2026-10-16). A direct request that names the deletion ("let's remove the lg modal") is itself the approval.
- Before deleting a variant, call `getInstancesAsync()` on it: it finds instances on every page without switching pages. Remap them, then delete. Instances on other pages can also be edited by id without switching pages (the Cover instance was). Remap in two passes: first instances with no INSTANCE ancestor (top level and inside main components), then re-query and swap whatever is left (those are overrides inside other instances); throw if any remain before deleting. Ignore instances that sit inside a variant you are about to delete (they go with it; on Date & Time the date pickers inside the doomed `State=filled` range-picker variants tripped the check). When the target has the same property keys (Pills and the old `_pill-tab-item` shared `#356:*` keys), `swapComponent` keeps the instance's property values. Before deleting a variable, check that no other variable aliases it (scan `valuesByMode` of every local variable for its id).
- Restyling instead of deleting (Slider knob, Sidebar item, Menu item): when a variant value goes away (focused) and another combination is needed (selected hover), rename and restyle the old variants into the new combination rather than deleting them and cloning new ones. No instances need remapping. (The `_menu-item` danger variants were renamed `Danger=true, State=rest`, so their 7 instances stayed linked.)
- Stale nested instances after a swap (File Upload, 2026-10-15): when a top-level instance is swapped and a variant is deleted in the same call, `getInstancesAsync()` can return stale nodes (instances inside the deleted variant, or old nested ids), and a nested instance that pointed at a deleted variant can survive as an orphan (main shows as `undefined/<set>/<value>`, old layers still inside). Skip instances whose ancestor is the deleted variant, re-fetch each by id before swapping, and afterwards check the swapped instance's nested instances' mains; swap any orphan by id (`I<instance>;<node>`) in the next call.
- Renaming variants: read every variant's properties (parse from `name`) before renaming any of them. Once one variant is renamed, `variantProperties` on the others throws "Component set for node has existing errors" until all are renamed. Renaming the variant names is also how a variant property is renamed (`Active` to `Selected`) or dropped (`Type`). New variants can be added under the old scheme with a new value (e.g. `State=range-hover`, `State=open-tmp`) and renamed with the rest after the deletions.
- Turning a plain component into a variant set (Modal, 2026-10-15): rename it to `Size=sm`, clone it for the other values, append the clones to the same frame, then `figma.combineAsVariants([orig, ...clones], frame, index)`. Existing instances stay linked to the original, now a variant. Add set properties (booleans) after combining, since clones drop property references.
- Text property gotcha: a TEXT component property's value is shared by every variant; setting `characters` on one variant's linked layer changes the default for the whole set.
- Cloning a variant inside its set (`v.clone()` then `set.appendChild`) drops the `componentPropertyReferences` on its layers (Segmented bar, 2026-10-15). Copy the references from the source variant's matching layers after cloning. A SLOT layer does not survive the clone as a SLOT at all (Accordion, 2026-10-15): remove the leftover layer, call `v.createSlot()` on the clone, relink it to the set's slot key, and delete the auto-created property (record the new keys by diffing `componentPropertyDefinitions` before and after). Clone before adding slots when you can (Menu item, 2026-10-15).
- Rebuilding a variant in place: keep the existing text and SLOT layers and reparent them into the new frames (their property references and instance overrides survive), build the new frames around them, then remove the old children. Used on Accordion, 2026-10-15, and on Slider (the labels and input instances kept their `👀` references after reparenting). When reparenting an old frame into a new HUG auto layout parent, check its vertical sizing: an old frame left at FILL height inside a HUG parent keeps its old height (the File Upload rows stayed 124 tall until `text` was set to HUG). A full rebuild that sets every layer's `componentPropertyReferences` explicitly (Sidebar item, 2026-10-15) works the same on clones and originals, so clone first, then rebuild every variant. Fresh layers work too: a new TEXT layer given `componentPropertyReferences = {characters: key}` picks up the property (calendar cells, 2026-10-15). Clear stale `minWidth`/`minHeight` on the variant root itself (the Calendar roots kept their old 208/220 minimums until cleared).
- Native slot technique in a variant set: `createSlot()` exists on a variant COMPONENT, not on the COMPONENT_SET, and each call makes its own property. Pattern: `set.addComponentProperty(name,'SLOT','',{description})`, then per variant `s = v.createSlot()`, relink with `s.componentPropertyReferences = {slotContentId: setKey}`, then `set.deleteComponentProperty(autoKey)`. The slot layer name and the property name are linked: renaming one renames the other (`set.editComponentProperty(key,{name})` renames it and keeps the key's number, e.g. `🌟 Slot#6012:0` became `🧩 Slot#6012:0`). `editComponentProperty` takes `preferredValues` (COMPONENT_SET key) and `slotSettings` (maxChildren etc.). Instances: `setProperties` cannot set slots; append content to the SLOT node found with `findAllWithCriteria({types:['SLOT']})` (works on nested instances too, e.g. a File tab item inside a File-tab row instance). Default content: appending an instance to the SLOT node inside the main variant works, and existing instances show it (Empty State, 2026-10-15). A SLOT node takes auto layout (`layoutMode`, AUTO sizing on both axes, centred alignment) and then hugs its content. Record each instance's old `🌟 Slot` swap value before deleting that property, so the content can be migrated in the next call. `createSlot()` appends the slot as the last child; move it with `insertChild` (Modal body top slot, 2026-10-15).
- Migration that keeps overrides (List, 2026-10-15): call 1 adds the native slots but keeps the old `Square - Slots` instances in the main variants (remove their `visible` reference, hide them, keep the swap reference). Call 2, per instance: get the old nested slot node by id (`I<instanceId>;<oldMainNodeId>`, or `<instanceId>;<oldMainNodeId>` when the instance id already starts with `I`), and the instance's SLOT node the same way; `nested.clone()` then `slot.appendChild(clone)`, `visible = true`. The clone keeps the nested instance's overrides (Avatar variant, button group content). Then in the same call delete the old instances from the main variants and delete the swap properties. Process top-level instances only once: an instance nested inside another instance inherits content added to its main, so also appending to the nested copy can double it (check slot child counts afterwards; on List none doubled). Processing instances in order of nesting depth and skipping any whose slot already has children also prevents doubling (Menu item, 2026-10-15).
- **Placeholder detection lost content (Table, 2026-10-15):** deciding "this old slot only holds the placeholder" by a component name starting with `Size=` misfired, because Avatar and Progress-bar variants are named that way too: 56 Avatar and Progress-bar slot contents on the Landing page were treated as placeholders and deleted with the old slots (Godwin chose not to restore them). Identify the placeholder only by its main's set id (`Square - Slots` `111:2727`), and never delete the old slot layers in the same call that decides what to migrate: migrate, return a count per content type, check it, then delete in the next call. (Dropdown, 2026-10-15: the menu-item migration broke this rule. One Stickersheet Menu's items (`588:41182`) returned null for the old nested slot id, and the old layers were deleted in the same call, so whatever they held is gone. Return misses and stop before deleting when any exist.) (Calendar, 2026-10-15: the call threw if any `🌟 Slot` value was not a `Square - Slots` variant; none was, so the old slots were removed in the same call.)
- Size every native slot: give the SLOT node a fixed width and height bound to a token sized for its content (File tab: `icon/sm`/`icon/md`/`icon/lg` per Size, Avatar: `avatar/slot-*`, List leading: `list/slot-*`, Menu item leading: `menu/slot`), items centred, and bind any content you append to the same token. Left at AUTO it shows as a huge 100x100 box (Godwin flagged this on File tab, 2026-10-15). Exception: a slot for open-ended content in a column (Accordion content, Calendar, Sidebar top and bottom) is FILL width and HUG height, hidden by its `👀` boolean until used. (Modal body top and bottom were built that way; Godwin then set them by hand to a fixed 352 width, HUG height.) Exception approved on List (trailing): the slot hugs its content, and is hidden unless its boolean is on. Table first used hugging slots too, but Godwin found them "unreasonably huge" (an empty hugging slot shows as 100x100), so Table slots are fixed squares bound to `table/slot-*` (2026-10-15): prefer fixed tokens. (The Sidebar top and bottom slots are FILL width, HUG height and hidden by default, as column content.) The Menu item trailing slot was built hugging and Godwin found it "unreasonably huge" too, so since 2026-10-16 it is a fixed square bound to `menu/slot` (24) like the leading one. The Dropdown trigger's `🧩 Chips` slot still hugs (the number of chips varies) and is hidden unless `👀 Chips` is on.
- Native slots in auto layout flow (not absolute, unlike Avatar): an empty slot stays a 100x100 placeholder and still takes the parent's gap, so it pushes content aside. Pair it with a `👀 Slot` boolean (default off) on the slot layer: `componentPropertyReferences = {slotContentId, visible: boolKey}`. Hidden takes no space and no gap. (Resizing the empty slot to 0.01 collapses it but the gap stays.) Turn the boolean on in instances that have slot content, and off in instances whose old slot only held the `Square - Slots` placeholder. When the slot has default content (Empty State), the boolean defaults on.
- Hidden nested instances cannot be found from outside (the Text Input's hidden `_trailing-input` inside the Time picker did not turn up with `findOne`): turn the controlling boolean on, edit, then turn it off again in the same call. (2026-10-15)
- Instance property gotcha: a component property added in a `use_figma` call is not visible on instances (`setProperties` throws "Could not find a component property") until the next call. Add properties in one call, set them on instances in the next. Defaults can be changed in the same call with `set.editComponentProperty(key,{defaultValue})`.
- Parallel write calls: on 2026-10-15 two `use_figma` write calls run side by side (Chip and Pills) left recreated copies of properties they had deleted, as unreferenced orphans (`#6143:*`), and a new boolean got the name `👀 Slot2`. Run destructive writes one at a time, and after any property deletion re-read `componentPropertyDefinitions` and delete unreferenced leftovers. (Alert and Toast ran in parallel without trouble; neither deleted properties.) Orphans also showed up after the Menu item slot migration (`👀 Slot ( L )#6242:103`, `👀 Slot ( R )#6242:104`, `Divider#6242:105`, unreferenced, deleted; the Sidebar chat was writing to the file at the same time).
- Temporary preview frames: build a Light and a Dark panel side by side (`setExplicitVariableModeForCollection` on each), take one `screenshot()`, then remove the preview in the same call. Set `clipsContent=false` on rows so focus rings show. Frames made with `figma.createAutoLayout` get a default white fill: set `fills = []` on preview rows, or the Dark panel shows white strips behind the content (happened on Badge). The preview's explicit modes can hide paint problems: also screenshot the component set itself (no explicit mode) after any paint rebuild. Set screenshots wider than about 500px at scale 2 come back cropped; use scale 1 or check positions instead of trusting a cut-off image. Preview content that grows (counts like "99+", long labels), not only the defaults. Several `screenshot()` calls in one script came back unreliable (one image dark, one blank) on Section tab; one preview frame with both panels and a single screenshot is the dependable check. (On Modals, Table, Sidebar and Date & Time, two or three screenshots in the same call all came back fine.) Contrast can be computed in the same call: `variable.resolveForConsumer(panel).value` gives each mode's color on its panel.
- Bound paints need a real base color: when writing a new fill or stroke with `setBoundVariableForPaint`, build the base paint from `variable.resolveForConsumer(node).value` (Light value), never a placeholder white. With a white base, the Notification main variants showed white surfaces and borders on the canvas (no explicit Theme mode) even though the bindings were correct.
- Removing a shadow (Chat-bubble, 2026-10-16): `setEffectStyleIdAsync('')` only detaches the style and leaves its shadows on the layer as local effects; also set `effects = []`, then check with a zoomed screenshot.
- Icon recolor gotchas: (1) hidden instances do not load their sublayers, so set `visible=true`, recolor, then set it back to false (this also applies to a hidden parent instance, such as a hidden overflow item, before searching it for its icon); (2) rebuild each vector's paints from the main component's paints (`vec.id.split(';').pop()` is the main node id) with `setBoundVariableForPaint`, so hidden or zero-opacity fills stay that way. Never write fresh opaque fills onto icon vectors. (3) `swapComponent` from a Lucide icon to Phosphor carries the old fill overrides across by layer name, so the Phosphor icon renders as a solid square: after swapping, call `resetOverrides()` on the icon instance or rebuild each vector's fills and strokes from the main as in (2). This happened on Section tab, the Section-tab overflow item and File tab close icons on 2026-10-15. A fresh `createInstance()` of a Phosphor icon (instead of a swap) avoids (3) entirely (Accordion, Pagination, Modal title, File Upload, Table, Sidebar, Calendar title bar, Dropdown trigger). (4) Swapping a `🌟 Icon` from Phosphor Placeholder to another Phosphor icon keeps the variant's stroke color overrides (Pagination disabled prev/next stayed `icon-minimal`, 2026-10-15; the Sidebar group's expanded header CaretDown to CaretUp swap kept `icon-subtle`; the pickers' CalendarBlank and Clock kept Text Input's `icon-subtle`). (5) Setting an Icon Button's `🌟 Icon` to Microphone (message bar, 2026-10-16) showed a dark filled shape in light mode: the swap carried a fill override onto the mic body. Rebuilding every vector's strokes and fills from the main's paints, bound to the button's own icon token (`icon-on-color`), fixed it. Check swapped icons with fills in a light preview.
- Sizing gotchas: old layers can carry raw `minWidth`/`maxWidth`/`maxHeight` limits that silently override a bound width or height. Clear them (set to null) when binding size, and set instances inside auto layout to HUG so their size comes from the main component's token, not a raw override. Bind size to width/height (visible in the W/H fields), not to min height; single-line fields use a fixed height. Phosphor main components are 32x32, so icon instances bind width and height to `icon/*` themselves; call `resize()` to the token value before binding, or a fresh instance in a HUG row can stay 32 tall (the Calendar title bar caret did). Pills that grow with content: fixed height bound to a token plus `minWidth` bound to the same token. `resize()` sets both axes to FIXED even on a frame made with `createAutoLayout`; set `layoutSizingHorizontal = 'HUG'` after it for boxes that grow with content (the Chip count box clipped "99+" until fixed). Setting `layoutSizingHorizontal = 'FILL'` on a hidden auto layout child does not take: show it, set FILL, hide it again (Empty State `actions`). An instance whose main binds its width to a variable stays FIXED when you set `layoutSizingHorizontal = 'FILL'` (no error): clear the instance's binding first with `setBoundVariable('width', null)`, then set FILL (Table-row basic cells stayed 128 and overflowed the row until fixed, 2026-10-15). When you bind a master's width to a token, check fixed-width instances of it inside other components: they take the new master width and can overflow (the Sidebar groups grew to 256 inside the 224 collection until set to FILL, 2026-10-15). FILL throws on an absolute child; bind its width to a token instead (the open Dropdown menu). A FILL child inside a HUG parent still pushes the parent to its own content width; in the Calendar the title and action bars are FIXED, bound to `calendar/width-*`.
- Changing a text layer's style: when a TEXT layer has its own variable bindings (fontSize, lineHeight, fontStyle, fontFamily) on top of a style, clear them with `setBoundVariable(field, null)` before `setTextStyleIdAsync`, or the old bindings keep overriding the new style (List description, 2026-10-15). After applying a style, `boundVariables` on the text still lists fontSize, fontStyle, fontFamily and lineHeight: those come from the style's own bindings and are expected. Note that `body-lg-bold` and the other `-bold` styles are Inter Medium (500), so they read only slightly heavier than regular in screenshots.
- New text styles: copy the font, size, line height, letter spacing and paragraph settings from the sibling style, then copy every entry of its `boundVariables` with `setBoundVariable`, so the new style stays tied to the Typography variables (`Body/body-lg-bold-underline`, 2026-10-15). `figma.moveLocalTextStyleAfter(newStyle, sibling)` places it next to its sibling.
- Outside strokes (focus rings, the Indicator ring) need `clipsContent=false` on every ancestor inside the component, or they get cut off. Exception: cells that touch their neighbours (Table) and items inside a clipping container (Menu item) use an inset 2px ring (`strokeAlign INSIDE`) instead. (Calendar cells kept the outside ring; it overlaps the neighbouring cell, which is fine for a single focused day.)
- Rotation gotcha: old components (and their instances) can carry a hidden rotation (the Tooltip pointers were at -90). Check `rotation` on the component and its instances before rebuilding contents, and reset it to 0.
- Wrapping text: a TEXT child set to FILL with `textAutoResize = HEIGHT`, inside a HUG parent whose `maxWidth` is bound to a token, wraps correctly at that max (used in Tooltip, Alert, Toast, Chat-bubble). Inside a fixed-width parent bound to a token, the same FILL + HEIGHT setup wraps at that width (used in Notification, Banner, Empty State, Accordion, List, Modal, File Upload, Menu item). Single-line truncation: `textAutoResize = HEIGHT`, `textTruncation = 'ENDING'`, `maxLines = 1` (File Upload filename, Table labels, Sidebar item labels, Dropdown value). This only works one level deep: a FILL text inside a FILL row inside a HUG parent with `maxWidth` collapses to its minimum (the chat document filename showed "I a…"), and a HUG row overflows the max instead. Give such a parent a fixed width bound to the token (the document bubble) or keep the text a direct child (2026-10-16).
- Shadow rule: simple boxes (cards, menus, modals, dropdowns, buttons, toasts, the Calendar popover) carry the elevation style on the surface itself (code: `box-shadow`). Composite shapes (tooltips and popovers with arrows, coach marks) carry it on a fill-less root that wraps body and pointer, so one shadow follows the combined silhouette (code: `filter: drop-shadow()` on the wrapper). drop-shadow has no spread, so composite shapes use `near` elevation (spread 0) for exact parity. All Elevation styles have "show behind transparent layers" on (`showShadowBehindNode: true`); without it, Figma cut the shadow out of the pointer's clipping frame and left a white box. Components that sit in the page flow (Banner, Tab bar, Accordion, List, File Upload, Table, Sidebar, Chat-list-item, Chat-navbar, Chat-message-bar) and surface-less ones (Alert) get no elevation. Menu has no pointer, so it is a simple box (`Elevation/neutral/mid` on its surface). Chat bubbles are flat by Godwin's choice (2026-10-16, after first getting the near elevation): no shadow; the tail and bubble still share a fill-less `body-wrap`, which is where a drop-shadow would go if one is ever wanted.
- Hover must not change a component's size: if a hover style differs only in decoration, add a sibling text style (e.g. `Body/body-lg-underline`, and `Body/body-lg-bold-underline` for bold text) rather than switching to a smaller style or overriding. Selection in a HUG row should not change width either: Section tab and File tab keep `body-lg` on the selected item and use color; Segmented bar and the Sidebar item can bold the selected label because they are equal or full width.
- Pressed states (Godwin, 2026-10-16): a pressed fill lasts a split second, so lower contrast on pressed is acceptable; don't change colors just to fix pressed-state contrast.
- Row dividers (Section tab, Tab bar, Modal title and action bar, Calendar title and action bar, Menu item, Chat-navbar): an absolute `divider` rectangle as the first child of the row (height bound to `stroke-md`, `border-subtle`, constraints STRETCH plus MAX or MIN), not a frame stroke, because a frame stroke draws over the children and would cover the selected underline. (Table cells keep their existing bottom border strokes on `Inner`: cell `stroke-sm`, header `stroke-md`. The Sidebar keeps a single-side frame stroke on its right edge: `stroke-md` right, `stroke-none` on the other sides; it has no children at that edge.)
- Heights from padding: when a header's height follows from its padding plus a 24px line, choose the padding so it lands on an existing control height instead of adding a token (Accordion: `space-xs` gives 32 = `control/sm`, `space-sm` gives 40 = `control/md`; Menu item: `space-xs`/`space-sm`/`space-md` give 32/40/48 = `input/*`); the item can still grow when the text wraps.
- Sizes: Godwin does not want a size that differs only by being denser (smaller type) unless a real context needs it (Accordion, 2026-10-15: sm and md differ by header padding only, both `body-lg`). Don't propose type-size drops for compactness by default. He also drops sizes that are only wider when the component can be resized in layouts (Modal lg removed, 2026-10-15). Table went from five sizes to three (sm/md/lg) on the same reasoning. Sidebar kept four sizes (sm to xl): they differ in row height, all `body-lg`. (Approved exception, Date & Time 2026-10-15: the sm calendar uses `body-md` for days and `body-sm` for weekdays, because 16px digits nearly touched in 24px cells.) Chat-bubble's `Length` short/long only changed the max width, so it was dropped for one `chat-bubble/max-width` token (2026-10-16).
