# Bland Design System: Claude Code Handoff

Oct 16, 2026 · @Godwin John

## Start here

Bland is Godwin's personal design system: a Figma UI kit he reuses across client projects, now being turned into code with a token pipeline and a docs site. The Figma side is finished; this doc is what Claude Code needs to build the code side.

- **What it is:** light and dark themes, a brand color that is swapped per project (edit the 12 `Brand/*` steps and everything follows), Inter for UI text, Geist Mono for code, Phosphor icons, 100% corner smoothing on every rounded corner.
- **Hard rule:** no hardcoded values in component code. Every color, size, space, radius, stroke, shadow and type value comes from a token.
- **Source of truth:** the [Bland Figma file](https://www.figma.com/design/32J76yQH71a7sENjf60RqD/Bland-Design-System) (file key `32J76yQH71a7sENjf60RqD`). Variables are local and not published as a library; Godwin works directly in this file.
- **Deeper notes:** the claude.ai project "Bland design system" holds `claude/bland-handoff.md` (component-by-component build notes and node ids) and `claude/bland-handoff-update-2026-10-16.md` (newer; wins where they disagree, including a stroke token rename the older file predates). The [Figma audit doc](https://claude.ai/code/artifact/8aba9baf-ab27-4b44-b98b-133ba5093546) records the foundation decisions.
- **Reading the file:** every variable and every component set has a description written for code; read those before guessing intent. Private building blocks start with `_` (for example `_menu-item`, `_fade`) and are not public components.

## Token architecture

Tokens sit in three layers: hidden primitives, a Theme layer with Light and Dark modes, and single-mode scales. Components only ever bind to Theme or scale tokens, never to primitives. 584 variables in 10 collections, plus 15 elevation styles and the text styles.

| Collection | Layer | Modes | Holds |
| --- | --- | --- | --- |
| `_Core Colors` | Primitive, hidden | 1 | `Brand/*`, `Neutral/*`, `Purple/*` scales (OKLCH) and their `Alpha/aN` steps |
| `_Functional Colors` | Primitive, hidden | 1 | `Red/*`, `Green/*`, `Amber/*` scales and alphas |
| `_Units` | Primitive, hidden | 1 | `unit/0` to `unit/640`, `unit/0-5`, `unit/1-5`, `unit/full` |
| `Theme` | Semantic and component | Light, Dark | `Text/`, `Icon/`, `Surface/`, `Border/`, `Shadow/`, `Scrollbar/`, `Fade/` and one group per component (`Button/`, `Indicator/`, `Badge/`, `Toggle/`, `TextInput/`, `Menu/`, `Table/`, `Messaging/`, `Code/` and so on) |
| `Spacing` | Scale | 1 | `space-none` 0 to `space-9xl` 256, `Layout/margin-desktop` 152, `Layout/margin-mobile` 24 |
| `Corner Radius` | Scale | 1 | `rad-null` 0, `rad-xs` 2, `rad-sm` 4, `rad-md` 8, `rad-lg` 16, `rad-xl` 24, `rad-rd` full |
| `Stroke` | Scale | 1 | `stroke-none` 0, `stroke-xs` 0.5, `stroke-sm` 1 (borders), `stroke-md` 1.5 (icons), `stroke-lg` 2 (focus rings), `stroke-xl` 4 |
| `Typography` | Scale | 1 | `family/`, `weight/`, `size/`, `line-height/`; every text style property is bound to these |
| `Effects` | Scale | 1 | Elevation geometry: `elevation/{near,mid,far}/{ambient,key}-{y,blur,spread}`, `elevation/x` |
| `Sizing` | Scale | 1 | Component dimensions: `control/*`, `icon/*`, `input/*`, `avatar/*`, `table/*`, `fade/*`, `scrollbar/width`, `logo/mark-*` and more |

**Rules that shape the export:**

- **Aliasing:** Theme tokens alias primitives in both modes. Component tokens point at primitives directly, not at another component's tokens, so they can diverge later. The one exception already in the file: `Badge/*` aliases `Indicator/*` on purpose.
- **Alpha primitives** are stored as an alias plus an opacity (`{color: alias, opacity: N}`), not as RGBA. The exporter must resolve these to the source color at that opacity.
- **`Fade/*-clear` tokens** are Figma-only drawing aids (a surface color at 0%). Do not export them.
- **Naming:** size steps follow value order (`xs` < `sm` < `md` < `lg`). Variant values are lowercase; property names are capitalized.
- **Descriptions:** every variable has one, written for code and the docs site. Export them alongside values.
- **Elevation:** 15 effect styles named `Elevation/{neutral,brand,danger,success,warning}/{near,mid,far}`. Each stacks a tight ambient layer and a soft key layer; geometry comes from `Effects`, colors from `Shadow/{family}-{ambient,key}`. In code each becomes one `box-shadow` variable that switches color in dark mode.
- **Text styles:** Display, Heading, Title, Body (including `-bold`, `-underline`) and `Code/*` in Geist Mono. `weight/semibold` (Inter "Semi Bold") and `weight/mono-semibold` (Geist "SemiBold") both exist because the families spell the style differently.

## Decisions code must follow

These were settled in Figma and should carry into code as written; where Figma could only approximate, the code behaviour is spelled out.

- **Dark mode:** Neutral mirrors (0 becomes 950, 50 becomes 900 and so on); color tints (50 to 300) become deep tones; color solids (400 and up) move two steps lighter. The Toggle knob stays white in both modes. The danger primary Badge and Indicator label stays white in dark mode (3.7:1) by Godwin's choice.
- **Focus:** a 2px ring in `Border/border-focused`, offset 2px, shown through a `👀 Focused` boolean in Figma. In code it is `:focus-visible`, never a separate state.
- **States:** rest, hover, pressed where relevant, and disabled. Focus is never a variant. Selected and checked are their own properties.
- **Slots:** components use Figma's native slots (`🧩` properties) for open content such as leading and trailing items, top and bottom slots, illustrations and the logo mark. In code these map to children or named slot props.
- **Property prefixes in Figma:** `👀` boolean, `✏️` text, `🌟` instance swap, `🧩` slot. Strip them for code prop names.
- **Corner smoothing:** every rounded layer is 100% smoothed. Code: `border-radius` plus `corner-shape: superellipse(n)` tuned to match; Chrome and Edge render it, Safari and Firefox fall back to plain rounding.
- **Icons:** Phosphor, stroked at `stroke-md` (1.5) and sized by `icon/*` (12, 16, 20, 24). Icon color follows the text beside it through the matching `Icon/*` token.
- **Overflow:** every scroll area that overflows shows a visible scrollbar (thumb `Scrollbar/thumb`, width `scrollbar/width`) and an edge fade, always both. In code the fade is a real `mask-image: linear-gradient(...)` on the scroll container, transparent only on edges that have hidden content, length `fade/md` (32) by default or `fade/sm` (16), updated on scroll, and a focused item scrolls clear of it. Figma draws it as a surface-colored overlay only because Figma masks were unreliable.
- **Truncation:** truncated text is not overflow. It always ends in an ellipsis, never a fade.
- **Tooltip placement** uses Floating UI names (`top-start` to `right-end`).
- **Descriptions** never use em dashes.

Scroll areas wired in Figma today: Menu, Calendar month and year views, Sidebar, Code snippet and Text Area. Table, Modal body, the chat list and tab rows do not scroll yet; if they do in code, they follow the same rule.

## Code stack

Bland is built raw: plain CSS on token variables, no Tailwind and no shadcn, with a headless library only for the behaviour of interactive components.

- **Styling:** tokens export as CSS custom properties (`--space-md`, `--surface-100` and so on); Dark mode redefines the Theme variables. Components use plain CSS or CSS Modules that read only those variables, so every value traces to a token.
- **Simple components are raw HTML:** Button, Badge, Indicator, Chip, Avatar, Alert, Banner, Toast, Progress, Breadcrumb, Table, Empty State, Accordion (on `<details>`), Toggle, Checkbox and Radio (on native inputs).
- **Interactive components use React Aria for behaviour only:** Dropdown and Menu, Modal, Tooltip, Tabs, Slider, Date and Time pickers, Pagination input. React Aria handles keyboard, focus and screen reader semantics; all styling is Bland's own CSS. Chosen over Radix Primitives and Base UI for its focus handling and date components.
- **Positioning:** Floating UI for Tooltip and Dropdown placement (Bland's placement names already follow it). Native `<dialog>` and the `popover` attribute are fine where they fit, but anchor positioning support is still uneven.
- **Framework:** React, assumed because React Aria needs it. Confirm with Godwin before scaffolding.
- **Linting raw values:** shadcn/lint is an agent-first linter for Tailwind design systems, so it does not apply here. Take its idea instead: Stylelint (with a strict-value rule) rejects any color, size, space, radius, stroke, shadow or font value that is not a `var(--…)`, and each error names the token to use and why, so an agent can fix it in one pass.

## Source of truth and sync

Each kind of information has one owner, and the others read from it instead of keeping copies. Bland is a one-person system (Godwin plus Claude), so the setup stays light: no review flow, no client-facing docs yet.

| What | Owner | How the others get it |
| --- | --- | --- |
| Token values, styles, component visuals | Figma file | Claude Code reads them through the Figma MCP connector and writes them into the repo; never edited by hand in code |
| Component behaviour, APIs, rules (overflow, focus, slots) | Code repo: `CLAUDE.md` plus a `docs/` folder | Figma component descriptions point to it |
| Planning and working chats | claude.ai project "Bland design system" | Reads the repo through the GitHub connector; keeps no copies of its own |
| Reading material | Docs site, built from the repo | Optional while Godwin is the only user |

**How Godwin works:** mostly designing in code through the Figma MCP. Claude Code reads a Figma frame or component (`get_design_context`, `get_variable_defs`, screenshots) and builds or updates the code from it, and can push code back to Figma when a design starts in code.

**Change flow:**

1. Change a token, style or component in Figma.
2. Run the token sync in Claude Code: it reads the variables through the Figma MCP, writes token JSON into the repo and regenerates the CSS, as one commit or pull request whose diff shows exactly what changed.
3. Components pick up the change because they only read tokens.
4. A decision made while coding goes into `docs/` or `CLAUDE.md` in the same commit, and the matching Figma description gets a one-line pointer.

**Keeping them honest:**

- A drift check (a script in the repo, optionally run as a weekly scheduled task) compares Figma's variables with the repo's tokens and reports any difference.
- No Code Connect (Godwin's call): the Figma MCP alone covers design-to-code. Instead, \`CLAUDE.md\` keeps a component map: for each component, its Figma set name, the code import, and how each Figma property maps to a prop (prefixes stripped, \`👀 Focused\` dropped since code uses :focus-visible). Claude Code reads it with what the MCP returns and updates it in the same commit whenever a component changes.
- Once the repo exists, its `docs/` and `CLAUDE.md` take over from this doc and from the project's `claude/bland-handoff*.md` files; retire those so nothing contradicts the repo. Until then, this doc is the hub.
